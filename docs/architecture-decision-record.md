# Architecture Decision Record

Newest first. Each entry gives the decision, why, and where the design covers it. Details are in [design/](design/software-factory-installer-design.md).

| Date | Decision | Why | Design |
|---|---|---|---|
| 2026-11-14 | Real-Homebrew integration tests sit behind the `integration` build tag (`make integration`). They run `scan`, `plan` and `doctor` read-only with a temporary state directory, and skip without Homebrew or as root. The only mutating test installs GNU `hello` through a one-entry `--catalog` and uninstalls it. It runs only with `FACMAN_INTEGRATION_MUTATE=1`, which CI sets on macOS runners only, and skips when `hello` is already present or the prefix belongs to another user. | Exercises the real `brew info`, tap and trust shapes that the fixtures only approximate (I-18), without ever changing a developer's machine by accident. | §7b; spec I1-14, D-12 |
| 2026-11-14 | The Homebrew installer runs as `/bin/bash <private temp file>` **without** `NONINTERACTIVE=1`, which the PRD named. It is downloaded to a `0600` file (3 tries with backoff) and never piped to a shell. | With `NONINTERACTIVE` set, `install.sh` checks sudo with `sudo -n` and aborts on macOS for every admin whose sudo needs a password, even though `facman` hands it the terminal. The installer turns non-interactive mode on itself when stdin is not a terminal. J can restore the variable. | §4a; implementation-notes I-32 |
| 2026-11-14 | Exit codes are 0, 1, 3, 4 and 64, with `doctor` alone returning 2. Precedence is usage (64), then bootstrap (4), then validation (3), then operation (1). Usage is decided before any I/O. `facman` with no command opens the TUI only when stdout is a terminal (otherwise the about text, exit 0), and needs stdin to be a terminal too (otherwise 64). | Deterministic results for scripts, and `facman \| cat` and CI smoke steps never hang. Keys, and with them consent, come only from a terminal. | §7; spec AD-14, D-6, I-49 |
| 2026-11-14 | `node@24` is never `brew link --force`d. Its keg `bin` goes first on every child's `PATH`, and the Summary prints the line for the shell profile. No recorded invocation may contain `--force`, and `plan.Validate` allows only `brew install`, `tap` and `trust`. | Forcing links overwrites files `facman` does not own. The allow-list is the safe direction. | §2a, §3a; spec AD-10, D-3, I-6 |
| 2026-11-14 | Mutating runs (`apply`, the TUI) take an exclusive `flock` on `<state dir>/facman.lock` from the scan through the run. A second run exits 4 naming the holder PID. Read-only commands never block: they skip their DB writes and warn. | Prevents double installs and a corrupt audit log, and keeps `scan` usable while an install runs. | §6; spec AD-9, D-10 |
| 2026-11-14 | Interrupted installs are reconciled at the next start. A package now detected through the operation's backend is recorded `managed`. Otherwise it stays `absent`, so the next `apply` proposes it again. | The developer consented to that install, so ownership stays honest. | §6; spec AD-8, D-8 |
| 2026-11-14 | State is in SQLite through `modernc.org/sqlite` (pure Go, WAL), with numbered embedded migrations and `meta.schema_version`. A newer or corrupt DB is exit 4 and is never touched. Binaries are static (`CGO_ENABLED=0`). | One self-contained binary for a bare machine, plus transactions for the audit log. | §6; spec AD-5 |
| 2026-11-14 | The CLI uses cobra with its usage output silenced and our own exit-code mapping. Both front ends are driving adapters (`internal/adapter/cli`, `internal/adapter/tui`) over one `adapter/session`, which composes the use cases. `cmd/facman` only wires, and takes environment facts as injectable `options` with no test-only flags or variables in the binary. | Keeps `cmd` thin and both front ends testable. One run path gives the TUI and headless runs the same audit trail. E2E tests can fake darwin, Linux and WSL machines on any runner. | §4, §8; spec AD-2, AD-3, AD-15, I-37 |
| 2026-11-14 | The TUI uses **Bubble Tea v2** (`charm.land/bubbletea/v2` v2.1.1) and Lip Gloss v2 (v2.1.0), the latest stable majors, without `bubbles`. It is a driving adapter (`internal/adapter/tui`) over the same session as the CLI. Sudo steps hand the terminal to the child with `tea.ExecProcess` while `execute` waits on a reply channel, so there is one executor for both front ends. `facman` with no command needs a terminal on stdout (else the about text, exit 0) and on stdin (else exit 64). | Resolves S-3 / R-OQ-4. Consent and keys come only from a terminal; one execute path keeps the audit log identical. | §8; spec AD-2, AD-14, AD-16 |
| 2026-11-14 | Deliver the PRD in increments that follow the phase table. **Increment 1 = Phase 0 + Phase 1 (MVP)**: identity, platform detection, detectors and `scan --json`, ownership states, embedded catalog and profiles, SQLite inventory with the audit log, bootstrap check and Homebrew install behind consent, brew-formula and brew-cask backends, `plan`/`apply --profile`/`status`/`doctor` with `--dry-run` and `--json`, and the install-only TUI. Scope and acceptance criteria are in the PRD's Delivery plan. | The full PRD is too large for one change. This is the smallest slice that is useful on its own and testable end to end. | §11; PRD Delivery plan |
| 2026-11-14 | Conflict detection and refusal (never `--force`) and item-level tap trust for Orca ship in Increment 1. Move-aside and `restore` follow in Increment 2. A conflicting package is skipped with its evidence, and the run exits 1. | Brew installs without the pre-flight can fail or clobber files, and Orca's tap needs trust. Refusing is the safe default. | §3a, §3b |
| 2026-11-14 | Headless `apply --profile` asks for consent on the terminal (`[y/N]`, default No), with no `--yes` flag. Non-terminal stdin is a usage error (64). Unattended runs use `-cl`. | Consent first. Only a reviewed file may stand in for a person. | §7, §7a |
| 2026-11-14 | Linux and WSL state lives at `${XDG_STATE_HOME:-~/.local/state}/facman/` (DB, `backups/`, `logs/`). Operation logs are pruned after 90 days, and `operations` rows never are. | Gives the design's "XDG equivalent" a concrete path, and keeps the audit trail with bounded disk use. | §6; PRD Appendix J |
| 2026-11-14 | Increment 1 end-to-end tests use a fake `brew` built from `testdata/` on Linux CI, plus a macOS integration job against real Homebrew. | Linux CI first: the whole slice is testable without network installs, and it is still checked against the real tool. | §7b; PRD Delivery plan |
| 2026-11-14 | Add `--no-paperclip` / `-nop` to suppress Paperclip from being considered for install. It is a per-run switch that overrides a listed Paperclip in `-cl` (with a warning), conflicts with `-ps` (usage error), and never touches an existing install. | J wants to change the default of always proposing Paperclip, for machines and builds that don't run it. | §7a |
| 2026-11-14 | The application is built as `facman`, with its entry point at `cmd/facman`. It replaces the working name `sfi`. Flags (`-cl`, `-hs`, `-ps`, `-os`, `-ts`) are unchanged. | J's naming decision. | §13 |
| 2026-11-14 | Add a `conflict` ownership state for unowned files at a backend's install path. Never overwrite or `--force`; offer move-aside-then-install. Third-party taps need explicit, item-level trust (Homebrew 6). | Found real conflicts on a lab Mac. Homebrew 6 requires tap trust. | §3a, §3b |
| 2026-11-14 | Every file format has a template, a schema and `facman validate`, and contract tests run on every build. | Users write these files first, and the tools' formats drift. | §7b |
| 2026-11-14 | Per-tool setup flags (`-hs`, `-ps`, `-os`, `-ts`) take a file. They run standalone or with `-cl`. | Seed agents and settings from git, not by hand. | §6b, §7a |
| 2026-11-14 | `facman apply -cl <file>` runs with no prompts, and the file is the consent. Risky options must be written in the file. It is designed Linux-CI-first. | Build machines and CI need repeatable, auditable runs. Most `-cl` runs are on Linux. | §7a |
| 2026-11-14 | Check for Homebrew and Node/npm on every launch. The TUI prompts, and `-cl` bootstraps automatically. | Machines may have nothing installed. | §4a |
| 2026-11-14 | Run Paperclip as a managed user service, on localhost by default. Remote access only on explicit opt-in. | Paperclip is a server, and the safest exposure is the default. | §6a |
| 2026-11-14 | Assume single-user machines, where the developer owns Homebrew. | Matches the lab. Avoids admin-user indirection. | §9 |
| 2026-11-14 | Use Antigravity CLI instead of Gemini CLI. | Gemini CLI is superseded, and its formula is being disabled. | §2 |
| 2026-11-14 | Homebrew is the primary backend on macOS, Linux and WSL 2, and npm is the second. macOS is the primary target. | One backend across platforms, and most of the catalog is in Homebrew. | §2a |
| 2026-11-14 | Install only missing tools, only with consent. Manage only what `facman` installed or the developer adopted. | Developers already own many of these machines. | §1, §3 |
| 2026-11-14 | Go + Bubble Tea, YAML catalog and profiles, embedded SQLite inventory. (Proposed in the design; confirmed by the Increment 1 build, see the entries above.) | A single static binary works on a bare machine. | §4, §5, §6, §8 |
